# TIU BSS code fixes — 28 October 2026

This update is based on the published Sites source `49d3cf4597af8ef27271c094b42613bcfd14f0ba` and preserves its Firebase Authentication plus Sites D1/R2 architecture. Firebase billing remains Spark. This pass changes source code only; it does not deploy, change cloud settings, grant roles, or modify member records.

## Current website fixes

- Private API requests recheck the initiating account after obtaining its token and before sending a draft. An account switch or signout prevents the request from reaching the server. Signed-out private requests fail before network access; the independent Admin session remains supported.
- Firebase auth callbacks ignore stale success and failure results after an account or token revision changes.
- Signout, account switches and privilege changes clear private forms and dialogs immediately. Background updates for the same account preserve unsaved edits.
- Suspended, rejected or missing-profile staff cannot read delegated registrations, pickup tokens or order records. Their own records remain available, and independent Admin access remains intact.
- Community-request retries preserve the saved response for identical normalized input. Conflicting content or recipients under the same request ID return HTTP 409 instead of silently discarding changes. Legacy records remain compatible.

The old Firestore 100-ticket limit is obsolete in the current native API, which returns the complete authorized registration list. No Firestore adapter was restored.

## Retained optional Firebase backend

The optional Functions source now requires a saved named profile before event registration, blocks self/super-admin role replacement through the staff form, and validates community-request retries. These changes do not add membership-approval or email-verification requirements for saved legacy profiles.

Its preflight resolves existing Windows Firebase CLI JavaScript entrypoints without a shell and reports the configured App Check provider. Documentation clearly distinguishes this optional deployment from the current website, which does not require Firebase Functions or Storage.
